# Repository map

## `registry/`
**Contains:** authoritative Excel workbook
`uzbekistan_nowcasting_v1.2_registry.xlsx`, historical snapshots V1.0 and
V1.1 under `archive/`, and change JSONs.
**May be modified:** only through a deliberate registry version bump with a
CHANGELOG entry.
**Must not be modified:** the archived V1.0/V1.1 workbooks and change JSONs.

## `config/`
**Contains:** `settings.yaml`, `registry_contracts.json`,
`siat_contracts.json`, `cbu_contracts.json`.
**May be modified:** to reflect real source-schema changes, with tests
updated to the new contract.
**Must not be modified:** to hide a source schema break without a matching
registry/contract change.

## `data/`
**Contains:**
- `data/raw/{provider}/{variable}/` — immutable payloads
- `data/processed/*.parquet` — per-variable cleaned data
- `data/master/{v1_monthly,gdp_quarterly,pilot_monthly}.{parquet,xlsx}`
- `data/master/build_manifest.json` — the run that produced the master
**May be modified:** by controlled operational reruns via the CLI.
**Must not be modified:** raw payloads must never be overwritten — new
retrievals are new files preserving all previous vintages.

## `src/uznowcast/`
**Contains:** registry loader, provenance/atomic-IO utilities, downloaders
(`io/`), parsers (`parsers/`), transforms (`transforms/`), validators
(`validation/`), master builder, `models/` (benchmarks, DFM, bridge,
midas, ensemble, evaluate, evaluate_v11, phase4b, phase4c, production),
and `operational/` (phase5a, phase5b, phase5b1, dashboard, dashboard5b,
dashboard5b1). Also `cli.py`, `pipeline.py`, `collect_vintage.py`.
**May be modified:** for Phase 5C challenger development, provided the
frozen Phase 4/5B.1 code paths are not touched.
**Must not be modified:** the code paths hashed by
`build_code_hash_inventory` (production_source role) without a new phase.

## `tests/`
**Contains:** unit + integration tests, `conftest.py`, fixtures under
`tests/fixtures/`, models tests under `tests/models/`, operational tests
under `tests/operational/`.
**May be modified:** to add coverage.
**Must not be modified:** the Phase 4C/5A/5B/5B.1 immutability tests
(`test_phase4_5a_5b_artifacts_remain_unchanged_after_phase5b1_run`,
frozen-hash checks) except by a phase that supersedes them.

## `scripts/`
**Contains:** the pilot builders, the registry V1.1/V1.2 generators, the
FX history downloader, the Phase 5B.2 cleanup script.
**May be modified:** to add new one-off automation.
**Must not be modified:** the registry generator scripts (historical
provenance).

## `results/`
**Contains:**
- `results/phase4a*_*` — Phase 4A / 4A.1 evidence (immutable)
- `results/phase4b_*` — Phase 4B candidate freeze + development metrics
  (immutable)
- `results/phase4c_*` — Phase 4C frozen holdout evaluation (immutable)
- `results/phase5a_*` — Phase 5A operational baseline (immutable)
- `results/phase5b/` — Phase 5B operational hardening (immutable)
- `results/phase5b1/` — Phase 5B.1 final production hardening (immutable)
- `results/frozen_validation_definition.json` — frozen validation
  contract (immutable)
- `results/production/` — canonical mirror of the Phase 5B.1 headline
  artifacts (regenerated by `scripts/phase5b2_cleanup.py`)
- `results/archive/README.md` — logical archive index; the archived
  files are kept in place under their original phase paths
- `results/phase5b2/` — Phase 5B.2 cleanup evidence
- `results/challengers/` — reserved for Phase 5C (not yet created)
**May be modified:** `results/production/` and `results/challengers/`.
**Must not be modified:** every `phase4*`, `phase5a*`, `phase5b/`,
`phase5b1/`, `frozen_validation_definition.json`, and any file listed in
`results/phase5b2/protected_artifact_manifest_before.csv`.

## `dashboard/`
**Contains:** historical HTML dashboards for Phase 5A / 5B / 5B.1, and the
canonical current `dashboard/current/uzbekistan_nowcast.html`.
**May be modified:** `dashboard/current/`, or new future phases.
**Must not be modified:** the three historical `phase5*_uzbekistan_nowcast.html` files.

## `docs/`
**Contains:** the Phase 2A → Phase 5B.1 methodology write-ups under
`docs/modeling/`, plus the Phase 3B audits (sparse-series, gold-proxy,
model-readiness tiers, historical extension), the release-metadata audit,
`source_findings.md`, plus the new `PROJECT_HISTORY.md` and
`REPOSITORY_MAP.md`.
**May be modified:** the top-level docs and future phase reports.
**Must not be modified:** the phase reports for Phase 4A → Phase 5B.1
without a superseding phase report.

## `metadata/`, `logs/`, `.tmp/`, `.venv/`
Runtime-only. All gitignored. Safe to delete and regenerate.

## Top-level files
- `PROJECT_STATE.md` — one-page operator status.
- `AGENTS.md`, `PROJECT_SPEC.md`, `CODEX_START_PROMPT.md` — governance.
- `README.md` — install + quick start.
- `pyproject.toml`, `requirements.txt` — environment definition.
- `.gitignore` — exclusions.

## Where to look

| Question | Answer |
|---|---|
| Where is raw data? | `data/raw/{provider}/{variable}/` (gitignored) |
| Where is master data? | `data/master/v1_monthly.{parquet,xlsx}` and `gdp_quarterly.{parquet,xlsx}` |
| Where is the registry? | `registry/uzbekistan_nowcasting_v1.2_registry.xlsx` |
| Where are transforms? | `src/uznowcast/transforms/` |
| Where are model specifications? | `results/phase4b_candidate_freeze.json`; `src/uznowcast/models/` for code |
| Where is the production runner? | `python -m uznowcast.operational` (Phase 5A) or `src/uznowcast/operational/phase5b1.py` (Phase 5B.1) |
| Where are the tests? | `tests/` |
| Where are frozen validation outputs? | `results/frozen_validation_definition.json`, `results/phase4c_holdout_*` |
| Where is the current production output? | `results/production/` |
| Where is the current dashboard? | `dashboard/current/uzbekistan_nowcast.html` |
| Where are the historical archives? | `results/phase4*_*`, `results/phase5b/`, `results/phase5b1/`, `dashboard/phase5*_uzbekistan_nowcast.html` — kept in place; see `results/archive/README.md` |
| Where should Phase 5C challengers write? | `results/challengers/` and `dashboard/challengers/` (to be created by Phase 5C) |
